# กระบวนการที่ 1: รับสมัครงานภายนอก แยกกลุ่มธุรกิจ (FU) — P1/WI-002+PM-001

## 1. กระบวนการเดิม
- ผู้สมัครเข้าเว็บเดียวรวมทุกบริษัท ทุกภาษา — ไม่รู้ว่าสมัครบริษัทไหน/สาขาไหน
- HR คัดแยกใบสมัครตามบริษัทด้วยมือ (เปิดไฟล์ทีละใบ ดูว่ามาจากที่ไหน)
- ผู้สมัครลาว/กัมพูชาต้องใช้ฟอร์มภาษาไทย/อังกฤษเท่านั้น ไม่มีภาษาแม่
- เปิด-ปิดบริษัทรับสมัคร = แก้หน้าเว็บ/แก้ไฟล์ (เสี่ยงข้อมูลเก่าหาย)
- ผู้สมัคร 1 คน สมัคร 2 ตำแหน่ง = กรอกข้อมูลส่วนตัวใหม่ทั้งหมด

## 2. จุดที่ AI เข้ามาช่วย
- AI คัดกรองใบสมัครตามคุณสมบัติ/CC อัตโนมัติ (WI-002 — ต่อยอดต้นแบบ recruitment-screening)
- แปลป้าย/ชื่อ/เอกสารรองรับ 4 ภาษา (TH/EN/LA/KH) — ชุดเดียว ไม่ต้องทำเว็บแยก 3 ชุด
- แจ้งผลผู้สมัครอัตโนมัติ (ผ่าน/ไม่ผ่าน/นัดสัมภาษณ์) ลดงาน HR ตอบแชท
- ตรวจจับใบสมัครซ้ำจากข้อมูลผู้สมัครเดิม (APPLICANT Stock)

## 3. กระบวนการใหม่ (13 ขั้น)
1. ผู้สมัครเข้าหน้า "ร่วมงานกับ PKG Group"
2. เลือก FU: 🟠THAI / 🟡RPLCG / 🔴🔵RAFCOG → ระบบตั้ง ภาษา + ธีมสี + ชื่อบริษัทภาษาแม่ อัตโนมัติ
3. เลือกบริษัท (COMPANY_MASTER เฉพาะ STATUS=ACTIVE)
4. เลือกสาขา (BRANCH_MASTER — บริษัทไม่มีสาขา = สำนักงานใหญ่)
5. เลือกตำแหน่งที่เปิดรับ (JOB_POSTING STATUS=OPEN)
6. กดยินยอม PDPA (เก็บหลักฐานความยินยอม)
7. กรอกใบสมัคร
8. อัปโหลดเอกสาร (รูป/วุฒิ/บัตรประชาชน)
9. ระบบ Validate ข้อมูล
10. สร้าง APPLICANT_ID → บันทึก DB1 (แยก APPLICANT Stock + APPLICATION)
11. แสดงเลขที่ใบสมัครให้ผู้สมัครเก็บไว้ติดตาม
12. ข้อมูลไหลเข้า Dashboard HR → Flow 10 ขั้นตอน ข้อ 4 อัตโนมัติ
13. ผู้สมัครติดตามสถานะได้เอง (ลดการโทรถาม HR)

## 4. ความซ้ำซ้อน/ความซับซ้อน
- เดิม: ทำเว็บ/ฟอร์มแยกตามประเทศ = ดูแล 3 ชุด แก้ทีต้องแก้ 3 ที่
- เดิม: เลขลำดับบริษัทในเอกสารไม่ต่อเนื่อง + ซ้ำ (พีซีแอล 2 ครั้ง, เลข 1.1.24/26 หาย, ปลวกแดงซ้ำ) → ใช้เลขลำดับเป็น key ไม่ได้
- เดิม: ปิดบริษัท = ลบข้อมูล → ประวัติผู้สมัครเก่าหาย
- เดิม: ข้อมูลผู้สมัครผูกกับใบสมัคร → สมัครซ้ำต้องกรอกใหม่หมด

## 5. กระบวนการใหม่หลังลดความซ้ำซ้อน
- ระบบเดียว + FU_ID ควบคุม Theme/ภาษา/Company List (Dynamic Theme — component ชุดเดียว)
- ใช้ COMPANY_ID รหัสระบบ (ไม่ซ้ำ 49 รายการ) แทนเลขลำดับที่แสดงบนเว็บ
- ปิดบริษัท = STATUS INACTIVE (Job ใหม่ห้ามสร้าง / Job เปิดอยู่ CLOSED / Public ไม่โชว์ / Application เก่าไม่ลบ / Audit Log บันทึก)
- APPLICANT แยกจาก APPLICATION → 1 คนสมัครกี่ตำแหน่งก็ได้ กรอกโปรไฟล์ครั้งเดียว

# กระบวนการที่ 2: โครงสร้างองค์กร (Flow การสรรหา ข้อ 1) — 4 เมนู

## 1. กระบวนการเดิม
- BU ต้องการปรับโครงสร้าง → เสนอบอร์ด → บอร์ดเคาะ → HR คีย์ลง Excel
- โครงสร้างถูกคีย์ซ้ำ 3 ที่: เอกสารบอร์ด / Excel HR / Flowchart ที่วาดมือ
- BMC ขออัตรากำลัง (Step 2) ต้องคีย์ข้อมูลบริษัท/หน่วยงาน/ตำแหน่ง/เงินเดือนใหม่ทั้งหมด
- Flowchart ล้าหลังของจริงเสมอ (วาดใหม่ทุกครั้งที่ปรับ)
- โครงสร้างภายนอก/ภายในปนกัน แยกไม่ออกว่าชุดไหนสำหรับอะไร

## 2. จุดที่ AI เข้ามาช่วย
- AI ตรวจความสมบูรณ์คำขอโครงสร้าง (ตำแหน่งซ้ำ/สายบังคับบัญชาขัดแย้ง/เกินกรอบเงินเดือน) ก่อนถึง PAO
- AI สรุปรายงาน Monthly: จำนวนคำขอ / อนุมัติ / ค้าง / โครงสร้างที่เปลี่ยน
- ดึงคำขอจากฟอร์ม GAS เข้าคิว PAO อัตโนมัติ + แจ้งเตือนเมื่อมีคำขอใหม่
- (อนาคต) แนะนำโครงสร้างเทียบ BU อื่นในกลุ่มเดียวกัน

## 3. กระบวนการใหม่ (8 ขั้น)
1. BMC/BU คีย์คำขอโครงสร้างผ่านเมนู ① ในเว็บ (BU/บริษัท/หน่วยงาน/ตำแหน่ง/จำนวนอัตรา/โครงสร้างเดิม/ที่ต้องการ/เหตุผล)
2. บันทึก STRUCTURE_REQUEST สถานะ REQUEST → แจ้ง PAO อัตโนมัติ
3. PAO เห็นคิวคำขอในเมนู ② (ภายนอก) หรือ ③ (ภายใน) — แยก dataset เด็ดขาด
4. PAO Set โครงสร้างแทนบอร์ด (บริษัท/BU/หน่วยงาน/ตำแหน่ง/จำนวน/ผู้รับใช้ทีม/สายบังคับบัญชา/ระดับตำแหน่ง/โครงสร้างเงินเดือน)
5. PAO กด APPROVE → บันทึก STRUCTURE_MASTER + สร้าง STRUCTURE_VERSION ใหม่
6. เมนู ④ Flowchart ราย BU อัปเดตเองอัตโนมัติตามโครงสร้างที่อนุมัติ (เลือก BU → บริษัท → ดึง Structure ล่าสุด APPROVED)
7. Step 2 ขออัตรากำลังคน: BMC เลือกจากโครงสร้างที่อนุมัติแล้วเท่านั้น — กรอกเฉพาะ "ขออัตรากำลัง" ไม่ต้องคีย์ข้อมูลซ้ำ
8. Audit Log บันทึกทุกการเพิ่ม/แก้ไข/อนุมัติ

## 4. ความซ้ำซ้อน/ความซับซ้อน
- คีย์ข้อมูลโครงสร้างซ้ำ 3-4 จุด (บอร์ด/HR/Flowchart/Step 2)
- Flowchart วาดมือ ไม่ sync กับของจริง
- โครงสร้างภายนอก (บริษัทในเครือ) กับภายใน (ทีม/หน่วยงาน PKG) ปนอยู่ในชุดเดียว
- BMC คีย์ข้อมูลบริษัทใหม่ทุกครั้งตอนขออัตรากำลัง — ผิดบ่อย ไม่ตรงโครงสร้างที่อนุมัติ

## 5. กระบวนการใหม่หลังลดความซ้ำซ้อน
- STRUCTURE DATABASE = Single Source of Truth ชุดเดียว
- อนุมัติครั้งเดียว → ไหลไปทั้ง Flowchart + Step 2 + ฐานข้อมูลขออัตรากำลัง อัตโนมัติ
- EXTERNAL / INTERNAL แยกตารางแยกสิทธิ์ชัดเจน (PAO เท่านั้นที่ Set ได้)
- Flowchart = view ที่ render จากฐานข้อมูล ไม่ใช่ไฟล์วาดมือ
