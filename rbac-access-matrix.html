🔐 Web PP7 — ตารางบทบาทการเข้าถึง (RBAC Access Control Matrix)

เอกสารประกอบการพัฒนา — ระบบบริหารบุคลากร PP7, Pakorn Group

แหล่งอ้างอิง: web-pp7/backend/Auth.gs (hasPermission + getDataScope)

1) RBAC 6 Roles — แบบออกแบบตั้งต้น (Design Baseline, 25 มิ.ย. 2569)

Roleขอบเขตการเข้าถึงผู้ใช้ตัวอย่าง
adminเข้าถึงทุกห้อง ทุก P (P1–P7)IT Admin
hr_managerP1–P7 อ่าน/เขียนHR Team
bu_managerP1–P4 ของ BU ตนเองBU Head
employeeดูข้อมูลตัวเอง + Self-Serviceพนักงานทั่วไป
auditorอ่านอย่างเดียว ทุก PAuditing Team
guestDashboard เท่านั้นผู้เยี่ยมชม
📌 ตารางนี้เป็นแบบออกแบบเดิม — ฝั่ง backend ปัจจุบันแมป role ตามทีมงานจริงของ PKG (ดูตารางถัดไป) โดย hr_manager ≈ pao, bu_manager ≈ bmc, employee ≈ member

2) Permission Matrix ที่ Implement จริง (backend/Auth.gs → hasPermission)

Resource admin pao
HR Admin		 bmc
Business Mgr		 pad
Training & Dev		 wcd
Welfare & Comp		 member
members ALL CRU R R R Rown
headcount ALL CRU CR — — —
recruitment ALL CRU RU — — —
assessment ALL CRU R — — —
matching ALL CRU RU — — —
performance ALL CRU RU R — Rown
development ALL R R CRU — Rown
compensation ALL R R — CRU —
welfare ALL R R — CRU CRown
dashboard ALL R R R R —

C = create · R = read · U = update · D = delete · ALL = create/read/update/delete/manage · — = ไม่มีสิทธิ์ · own = เฉพาะข้อมูลของตนเอง

⚙️ หลักการตรวจสอบสิทธิ์ในโค้ด: admin ใช้ wildcard '*' ครบทุก action · role อื่นตรวจทีละ resource → resourcePerms.includes(action) · role ที่ไม่อยู่ในตารางจะถูกปฏิเสธทันที (return false)

3) Data Scope — ขอบเขตข้อมูลที่มองเห็น (backend/Auth.gs → getDataScope)

RoleScopeคำอธิบาย
adminallเห็นข้อมูลทุกแผนก / ทุก BU
paoallเห็นข้อมูลทุกแผนก / ทุก BU (HR กลาง)
bmcdepartmentเห็นเฉพาะข้อมูลแผนก/BU ของตนเอง
paddepartmentเห็นเฉพาะข้อมูลแผนก/BU ของตนเอง
wcddepartmentเห็นเฉพาะข้อมูลแผนก/BU ของตนเอง
membermember_id ของตัวเองเห็นเฉพาะข้อมูลตัวเอง (filter ด้วย member_id จาก session)

4) สถานะการพัฒนา & หมายเหตุสำหรับทีมพัฒนา

หัวข้อสถานะรายละเอียด
RBAC 6 roles (hardcode)✅ ทำแล้วฝังใน Auth.gs ฟังก์ชัน hasPermission()
Data Scope filtering✅ ทำแล้วฟังก์ชัน getDataScope() — admin/pao = all, bmc/pad/wcd = department, member = own
Audit Log ทุก action✅ ทำแล้วObject AuditLog บันทึก user_id, action, entity, old/new value, timestamp
หน้าจัดการ Role แบบ Dynamic⏳ ยังไม่ทำปัจจุบันแก้สิทธิ์ต้องแก้โค้ด — ควรทำ auth-admin-panel ให้จัดการ role จากหน้าเว็บ
Deploy Backend GAS⏳ รออนุมัติโครงสร้าง Auth/Database ยังไม่ deploy ขึ้น Google Web App
💡 ข้อเสนอแนะต่อทีมพัฒนา: แนะนำให้ sync ชื่อ role ระหว่าง 2 ชุดให้ตรงกัน หรือเพิ่ม alias mapping (hr_manager→pao, bu_manager→bmc, employee→member, auditor→อ่านอย่างเดียว) เพื่อไม่ให้เอกสาร presentation กับโค้ดจริงต่างกัน
